# Bot 协作

Grok Bot 的核心不是「一个助手」，而是**一个团队**。这里实现了三种协作方式。

## 1. 委派（同步）

A 把子任务交给 B，**等 B 做完**再继续。

```
研究官：「帮我查一下竞品定价」
  → delegate_to_bot(botName="研究官", task="...")
  → 等它返回结果
  → 研究官转述给用户
```

适合：需要对方结果才能继续的场合。

## 2. 留言（异步）

A 给 B 发一条消息，**不阻塞**，B 下次对话时在系统提示里看到。

```
研究官 → message_bot(botName="撰稿人", message="今晚 8 点前要一篇 300 字短文")
```

实测：撰稿人下次被叫起来第一句话就是
「团队有一条待办：研究官今晚 8 点前需要一篇 AI Agent 短文」。

适合：转交线索、同步进度、分派不紧急的活。

## 3. 群聊（多方讨论）

发起一个房间，**多个 Bot 依次就同一话题发言**。

```
start_group_chat(topic="产品该不该做移动端", members=["撰稿人","技术负责人"])
```

每个成员用自己的系统提示词回答，发言全部记录到房间里。

实测输出（撰稿人视角）：

> **该做，但先做「场景切片」，不做全量 App。**
> - 用户场景：只有「高频、短时长、随时触发」的需求真正需要移动端
> - 成本：主要成本来自长期投入，不是开发本身
> - 匹配度：移动端应定位成轻量入口，负责「触达和确认」

适合：需要多视角决策、方案评审。

## 数据在哪

```
%APPDATA%\Grok Bot\collab\
  _inbox.json          未读留言队列
  room-xxxx.json       各群聊房间记录
```

留言被读取后会从队列移除（不会重复出现）。房间保留最近 200 条。

## 三个工具

| 工具 | 同步性 | 用途 |
| --- | --- | --- |
| `delegate_to_bot` | 阻塞等结果 | 需要对方产出 |
| `message_bot` | 不阻塞 | 通知、转交、分派 |
| `start_group_chat` | 依次等待 | 多方讨论 |

Bot 会自己判断用哪个。你也可以直接在对话里说
「把这个交给撰稿人」「拉个群讨论一下」。

## 局限

- 群聊是**串行**的（一个说完下一个），不是并行
- 子 Bot 的中间过程不显示在主对话里，只回传最终结果
- 没有「@某人」的实时路由，靠模型主动调用工具
- 跨 Bot 的记忆是隔离的（除了留言）
