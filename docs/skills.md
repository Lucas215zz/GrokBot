# 技能（Skill）

技能是「可复用的做事流程」。Bot 执行任务时会先看有哪些技能，
命中就读取完整步骤再照做——而不是每次凭空发挥。

## 存在哪

```
%APPDATA%\Grok Bot\skills\
  <技能标识>\
    SKILL.md          ← 技能定义（必需）
    scripts\          ← 可选：辅助脚本
```

界面上「左栏 → 🧩 技能 → 打开目录」可直接打开这个文件夹。

也可以直接手动建目录、写 SKILL.md，界面会立刻看到（无需重启）。

## SKILL.md 格式

与 Codex 的 skill 格式兼容：

```markdown
---
name: 写日报
description: 需要生成工作日报、周报时使用。会按固定结构输出 Markdown 文件。
---

# 写日报流程

## 步骤
1. 用 `run_command` 执行 `Get-Date -Format "yyyy-MM-dd"` 取当天日期。
2. 创建 `daily-report.md`。
3. 按固定结构写入。
4. 用 `read_file` 读回确认。

## 约束
- 内容要具体，不要写空话。
```

- **name**：显示名
- **description**：**最重要**。模型靠这句话判断「这个任务该不该加载这个技能」，
  所以要写清楚「什么时候用」
- 正文：具体步骤、命令、验收标准、禁止事项

## frontmatter 支持范围

头部按 **Codex 兼容的 YAML 子集**解析，从 Codex 目录直接拷进来通常无需改写：

- 普通标量：`name: 写日报`
- 单 / 双引号字符串（双引号内支持 `\n` `\t` `\"` 转义）
- **块标量**：`description: |`（字面保留换行）与 `description: >`（折成空格）
- **嵌套映射**：`metadata:` 下的子键（如 `short-description`、`author`）
- 行内注释 `# ...`（引号内与块内容除外）
- CRLF / 末尾无换行 / 带 BOM

注意：

- 系统提示里注入的**技能清单只显示单行简介**（多行 description 会被压成一行）；
  需要完整多行内容的，`use_skill` 读取时给的是原文。
- 界面编辑只改 name / description / 正文；导入时携带的其它 frontmatter 字段
  （如 `metadata`）在保存后仍会保留。
- 正文里的 `---` 不会被误当成头部结束（只解析文件开头的那一个 frontmatter 块）。

回归：`npm run verify:skills`（46 项，含真实 Codex 技能原文、往返保存）。

## Bot 怎么调用技能

两步走（渐进式加载，避免撑爆上下文）：

1. **启动时**：技能清单（name + description）自动注入系统提示，模型知道有哪些
2. **需要时**：模型调用 `use_skill` 读取正文，再按步骤执行

实测日志：

```
use_skill    {"name": "写日报"}          ← 先读技能
run_command  Get-Date -Format "yyyy-MM-dd"  ← 按技能第 1 步
write_file   daily-report.md             ← 按技能第 2 步
read_file    daily-report.md             ← 按技能验收步骤
```

如果任务没有匹配的技能，模型不会硬套，会自己用基础工具处理。

## 用 `@技能名` 直接调用（全局通用）

上面那种「模型自己判断要不要加载」在模糊任务上很好用，但当你**明确**想用某个流程时，
没必要让模型猜。在输入框里用 `@技能名` 直接点将，正文会被**强制加载并严格执行**。

```
@写日报 把今天做的整理成日报
@规范提交 帮我把这些改动提交
@tiktok-store-information 采集这几个店铺
```

- **输入即补全**：敲 `@` 立刻弹出技能候选（按 `id` 或 `name` 过滤，支持中文），
  `↑`/`↓` 选择、`Tab` 或 `Enter` 确认、`Esc` 收起；点候选也可以。
- **两种写法都认**：`@写日报`（name）或 `@write-daily-report`（id），大小写不敏感。
- **长名优先**：`@creatorpicks-batch-upload-products` 不会被截成更短的名字。
- **重复只算一次**；`@a@b` 连续写也能都识别。
- **不误伤**：邮箱 `abc@qq.com`、URL 里的 `@` 不会被当作技能引用。
- **用户意图优先**：即使该技能不在当前 Bot 的「启用的技能」清单里，`@` 了也会加载，
  提示里会注明「该技能未在本 Bot 启用列表，但因用户 @ 指定而加载」。
- **名字打错不报错**：不存在的 `@xxx` 会被忽略，并在系统提示里说明「已忽略」。
- 对话、委派、群聊、定时例程四个入口都支持 `@`（都在 `buildAgentContext` 里统一解析）。

界面会在对话流里出一条「已加载技能」轨迹，让你看到这次按哪个技能在跑。

回归：`npm run verify:mentions`（31 项，覆盖解析 / 读正文 / 未启用也加载 / 强制注入系统提示）。

## 按 Bot 隔离

在「Bot 设置 → 启用的技能」里勾选：

- **不勾选任何技能** = 该 Bot 可用全部技能
- **勾选若干** = 只能用这几个（`list_skills` 里也看不到其他的）

实测：只启用「规范提交」的 Bot 被要求写日报时，
它的 `list_skills` 里没有「写日报」，因此不会误用。

## 什么时候该写技能

满足以下任意一条就值得沉淀成技能：

- 同样的事做过 2 次以上
- 步骤固定、容易漏
- 有明确验收标准
- 涉及危险操作，需要固定审批点

## 和「定时任务 / Routines」的关系

技能是**流程**，Routine 是**按计划自动跑某个流程**。
先有稳定的技能，再把它挂上时间表，才不容易出错。

例程的提示词里同样可以写 `@技能名`（见 `routines.md`）。
